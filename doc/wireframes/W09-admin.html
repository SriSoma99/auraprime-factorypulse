Amendment 2026-11-05 (ADR-040): users, roles and screen access

  • Users and roles. One row per user of the tenant with a role picker. Disabled for your own row ("another admin must change it") and for API keys and agent tokens ("keep their issued role").
  • Screen access by role. Pick a role, then set each screen to Hidden, View or Use. Each row shows the config default, a "changed" chip when overridden, and Reset. The admin role's Admin row is locked.
  • Every change shows its audit reference (AUD-…) and applies on the user's next request. The API enforces the same rules. Approval tiers are not editable here (policy.role_max_tier, invariant 2).
  • States: loading, error, view only (actions disabled), permission denied (route redirects to the first permitted screen). The default matrix is in 02 section 4.4.
  • ADR-012 & Invariant 4: Every query and event enforces mandatory tenant_id isolation via database RLS.
  • Role Architecture: Enforces separation between ACT-2 (technician checklist execution), ACT-3 (tier-1 approval), and ACT-4 (tier-2 RCA engineering sign-off).
